## Duplicates and near duplicates (flagged, kept)
Near duplicate = a later record by the same agent for the same client within 10 minutes of an earlier one, with the same customer id, or a customer id one digit away. Identical timestamps are counted as duplicate events instead.

| Flag | Records | Agents | Max per agent |
|---|---|---|---|
| near duplicate one digit customer | 549 | 21 | 85 |
| near duplicate same customer | 77 | 33 | 7 |
| duplicate event | 0 | 0 | 0 |

These are kept because resubmitting a customer is one of the behaviours the features measure; removing them would remove signal. Record-level flags are in the run folder (`record_flags.csv`), not in the cleaned data, so they never become model inputs.

## Failed and pending activations
Status mix: completed 91.7%, failed 5.3%, pending 3.0%. **Kept, and counted as submissions.** Features measure attempted activations, fake customers are the submissions most likely to fail, and the live backend counts every record. Status is independent of fraud in this synthetic data, so the choice has no effect here and cannot be validated on it.
